## 0. 一页纸

### 0.1 最终形态

Nova Agent 是一个本地优先、可验证的 AI 工作台，覆盖三条工作流：

| 工作流 | 用户得到什么 | 可信基础 |
|---|---|---|
| **开发** | 对话 → 检索/修改 → 真实执行 → 人工审查 → Git/PR | 每条结论可回到代码位置、命令、退出码、运行环境与人工决策 |
| **文档** | 一个文档工作区，论文/报告/简历三种项目类型；从需求澄清到成稿、排版、导出 | 原文件不被静默覆盖；版本可回退；论文确认绑定内容；简历只重组真实事实 |
| **远程** | 手机扫码进入工作台，看进度、收完成通知、处理低/中风险审批、停止任务 | 本地不暴露公网端口；设备签名；高风险仍在本地确认；全程审计 |

三条工作流共用**同一个 Agent 循环、权限引擎、后台任务、审计与证据模型**。不另建三套 Agent，也不把远程做成第二个执行面。

### 0.2 五条用户要求 → 路线图落点

| 用户要求 | 落点 | 首次可见 |
|---|---|---|
| 1. 开发模式对齐主流，并有不同与创新 | M2 PR/CI/评审闭环；M3 证据包与本地-服务器可比；M4 跨仓库影响；M5 代码→文档断言链 | M2 |
| 2. 论文模式 0→1 动态对话，从选题到成稿 | M3 七阶段状态机 + 主动澄清 + 分段草稿 + 作者确认 | M3 |
| 3. 远程控制：手机看进度、发指令、收完成通知 | M2 只读进度/完成通知/停止；M3 审批/继续/有限指令；M4 可选微信/企微适配 | M2 |
| 4. 去掉宣传页与真实产品里的 AI 口吻 | M1 文案基线与首批清理；之后每个里程碑持续检查 | M1 |
| 5. 本地目录多格式写作、排版优化/转换、简历 | M2 文档底座；M3 论文多格式与阶段化；M4 简历 MVP；M5 排版优化/转换 | M2 |

### 0.3 推荐执行顺序

```text
M1 契约与事实层
   ↓
M2 日常可用：文档底座 + 开发 PR 闭环 + 远程只读/停止 + 文案清理
   ↓
M3 核心体验：论文七阶段 0→1 + 证据包 + 远程审批
   ↓
M4 扩展人群：简历 MVP + 跨仓库影响 + 可选微信/企微适配
   ↓
M5 证据闭环：代码→文档 + 排版优化/转换 + 生态扩展
```

M1 是强制的：没有统一事实模型，后面的证据包、文档确认、远程进度都会各说各话。  
M2 起，四条工作流可以并行；如果只有一个人推进，建议顺序为：**文案清理 → 文档底座 → 开发 PR 闭环 → 远程只读/停止**。

## 1. 不变量与红线

这些约束不随阶段调整而改变。任何新功能如果触碰红线，必须 redesign 或拒绝，不得静默降级。

### 1.1 产品与隐私

1. **本地优先**：文件在用户磁盘上；BYOK；无遥测；Apache-2.0。
2. **只发必要内容**：默认只向模型发送用户勾选的段落、JD 片段或单条事实；发送前显示实际离开本机的内容。
3. **不隐藏 AI 参与**：保留“AI 草稿”“AI 使用声明”；不承诺“降 AI 率”“降低 AIGC 痕迹”。

### 1.2 论文与文档

4. **论文保留作者实质参与**：全流程辅助、分段草稿、作者确认；不提供无人参与的整篇学位论文代写。
5. **普通报告可以完整起草**；简历只重组真实事实，不编造经历、数字、证书或时间。
6. **不伪造引用、数据、实验结果**；不提供降重、AIGC 规避、知网/维普/万方抓取。
7. **不静默覆盖原件**：写入前哈希校验；冲突检测；版本可回退；PDF 只作为终态导出与证据，不作为可逆编辑源。
8. **不承诺学校/招聘方结果**：格式检查、ATS 兼容检查只报告“本工具看到了什么”，不承诺通过率或录用率。

### 1.3 开发与交付

9. **不自动合并、不自动发布、不无人值守跨仓库写入**；外部副作用必须用户明确授权。
10. **不把“有输出”当“通过”**：失败、未运行、跳过、工具缺失必须分开；部分通过不得显示为全部通过。
11. **不用审批替代隔离**：本机执行必须明确标注“无容器隔离”；隔离等级、网络策略、工作目录范围必须随结果展示。
12. **不伪造性能/用户数字**；不把自动检查称为学校或企业合规认证。

### 1.4 远程

13. **本地不暴露公网端口**；只主动出站到受控中继。
14. **远程不能批准高风险操作**：删除文件、任意命令、修改系统配置、访问密钥/凭据、外发源码、支付类操作一律本地确认。
15. **微信不是控制面**：个人订阅号不能认证，不能用参数二维码/网页授权/客服消息/模板/订阅通知；微信只作为扫码入口或可选通知适配，消息不视为 E2EE。
16. **不做“点开链接即自动绑定”**；一次性 token + 本地确认 + 短验证串 + 可撤销设备。

### 1.5 架构

17. **一个 Agent 循环**：远程指令只映射为有限意图，不直接进入 shell，不绕过本地权限引擎。
18. **一个文档引擎**：不为论文、报告、简历各写一套编辑器/导出器。
19. **一个事实模型**：验证结果、证据主张、进度事件、审批请求、文档变更、阶段事件共享 schema。
20. **复用优先**：能扩展现有 Agent 循环、权限、后台任务、轨迹、沙箱、引用校验的，不另建执行路径。

### 2.2 共享服务

| 服务 | 职责 | 复用/新建 |
|---|---|---|
| Agent 循环 | 对话、计划、工具调用、子代理、后台回合 | 复用 |
| 权限/审批 | 风险分级、逐次批准、敏感工具策略 | 复用并扩展远程意图 |
| 执行器 | Docker 沙箱（服务器）/ 本机 HostExecutor（本地） | 复用，补隔离事实 |
| Job/轨迹 | 长任务、进度、事件、恢复 | 复用，补统一进度事件 |
| 证据服务 | 验证结果、主张、环境清单、未证明项 | 新建 |
| 文档引擎 | IR、变更、版本、预览、导出 | 新建 |
| 论文阶段 | 七阶段、readiness、artifact、阶段事件 | 新建 |
| 简历 | 主档案、事实库、JD 快照、岗位版本 | 新建 |
| 远程连接器 | 出站 WSS、设备密钥、命令信封、审计 | 新建 |

### 2.3 数据与信任边界

1. **本地文件是文档的事实源**；数据库存索引、事件、确认和版本元数据，不替代磁盘文件。
2. **模型只收到必要片段**；文档全文、JD 全文、源码全文都不默认上传。
3. **远程中继只看到密文和最小路由元数据**；手机私钥不离开设备；桌面密钥由 OS 安全存储保护。
4. **本地权限引擎是唯一执行者**；远程审批只是在现有审批链上增加一个因子，不能降级风险。
5. **审计分两份**：本地 append-only 记录执行与决策；中继记录设备、命令、路由与撤销；两边可用事件 ID 对上。

## 4. 里程碑

### 4.0 依赖与并行关系

| 里程碑 | 硬依赖 | 可并行的工作 |
|---|---|---|
| M1 | 无 | 文案清理、文档 IR 调研、远程威胁建模 |
| M2 | M1 的 CAP-01/02 | 文档底座、开发 PR 闭环、远程只读/停止；三者互不阻塞 |
| M3 | M1 + M2 文档底座；CAP-04 依赖 CAP-01/02 | 论文七阶段、证据包、远程审批可并行 |
| M4 | M3 文档引擎与项目类型；CAP-05 依赖 CAP-04 | 简历 MVP、跨仓库影响、微信/企微适配可并行 |
| M5 | M3/M4 的证据与文档能力 | 代码→文档、排版优化/转换、独立移动端评估可并行 |

并行不等于同时开工：如果只有一个人，按 §0.3 的顺序推进；如果多人，按上表拆分，但共享 schema 的改动仍由一人统一。

### M1 契约与事实层

**目标**：先把“什么算验证过、什么算文档变更、远程能发什么”定义清楚。此阶段只做底座与文案，不铺新界面。

**交付**

1. **CAP-01 统一验证结果**：`passed / failed / not_run / skipped / unsupported`；绑定 commit 或工作区 diff 摘要、规范命令、退出码、测试收集/通过/失败/跳过数、开始/结束时间、日志定位。禁止仅凭模型自述或“无输出”判定通过。
2. **CAP-02 隔离事实披露**：每条验证/命令显示执行模式（容器/本机）、隔离等级、网络策略、工作目录范围、敏感环境剥离情况。无隔离时不得展示为隔离执行。
3. **文档 IR/变更/版本契约**：定义文档中间表示、变更集、版本、哈希、确认绑定、冲突与回退语义；建立 DOCX/MD/PDF 样例保真测试集与“不支持清单”。
4. **远程事件/意图契约**：定义进度事件、审批请求、命令信封、风险映射、设备与审计字段；本阶段不实现网络。
5. **文案基线**：盘点宣传页、`/guide`、论文对话、Builder 对话、Agent 系统提示中的 AI 口吻与夸大表达；建立产品语气词表与禁用主张；完成首批清理。

**验收**

- [ ] 人为制造失败、跳过、未运行、工具缺失四类样例，报告与实际命令结果逐项一致；同一 commit 重跑可对比。
- [ ] 同一任务分别在 Docker 与本机模式运行，结果页显示不同执行环境与安全边界；本机结果不能通过任何“安全/隔离”筛选。
- [ ] 至少三份样例（新建 MD、已有 DOCX、PDF 导出）有预期解析/渲染结果与不支持清单；不得静默丢内容。
- [ ] 远程事件/意图 schema 有文档、有风险映射表；本阶段无新增网络监听。
- [ ] 文案词表与禁用主张落地；宣传页/`/guide` 首批清理完成；产品提示词首批清理完成。

**不做**：新文档编辑器、论文阶段界面、远程网络、PR 闭环。M1 的产出是后续所有阶段的“事实语言”。

### M2 日常可用

**目标**：让一个真实用户在同一天里完成“写一份报告并导出”“让 Agent 改代码并开 draft PR”“在手机上看进度并停止任务”。

**交付**

1. **开发：CAP-03 PR/CI/评审闭环**
   - 连接 GitHub；用户明确授权后创建 draft PR；展示 CI 状态与评审意见；按评论继续修复。
   - 合并、推送主分支、其他外部副作用仍由用户最终决定；不做自动合并。
   - 交付页复用 M1 的验证事实，不再另做一套“完成”判断。
2. **文档：底座 MVP**
   - 用户选择本地目录；创建/修改 Markdown；报告项目从需求到完整起草。
   - `source/manuscripts/assets/exports/.nova` 目录；哈希校验；原子写；外部修改冲突检测；版本/备份/回退。
   - Pandoc 导出 DOCX；LibreOffice 按需下载并校验哈希后用于 PDF 预览；下载失败显式降级，不静默改用服务端转换。
   - 诊断报告：哪些格式/对象已支持、哪些不支持、哪些可能失真。
3. **远程：只读薄片**
   - 本地出站连接器到受控中继；无公网监听。
   - 桌面生成一次性二维码/链接；手机打开工作台，生成设备密钥；本地确认 + SAS 核对后绑定。
   - 只读进度：任务状态、阶段、百分比、脱敏摘要。
   - 完成/待审批通知：应用内 + 邮件；可选 Web Push；只含任务 ID、脱敏摘要、一次性链接。
   - 停止：最高优先级、始终可用、幂等；设备撤销；本地+中继双份审计。
4. **文案：首批清理上线**
   - 宣传页、`/guide`、论文对话、Builder 对话、Agent 系统提示的首批修改随本阶段发布。
   - 所有对外承诺与已上线能力对齐；未上线能力不写成“已有”。

**验收**

- [ ] 测试仓库走完“Issue → 改动 → 验证 → draft PR → CI → 评审意见 → 修订”；未授权时无远端写入；自动合并不存在或默认关闭。
- [ ] 创建一份报告 MD，完整起草并导出 DOCX/PDF；外部修改不静默覆盖；可恢复上一版；PDF 组件缺失时明确提示。
- [ ] 本地端口扫描无新增公网监听；绑定 token 第二次使用、过期使用、错误 SAS 均失败。
- [ ] 手机能看到脱敏进度；完成通知不含 API Key、源码、完整路径、令牌、客户数据；停止命令生效且幂等。
- [ ] 撤销设备后旧会话语义立即失效；本地离线时中继命令不会在恢复后盲目执行。
- [ ] 文案检查通过：无“让 AI 理解…”“智能/全面/轻松/无缝”等空话；无“降 AI 率”承诺；AI 草稿标识保留。

**不做**：远程审批/继续、论文阶段、简历、跨仓库、排版优化。M2 的远程只做“看”和“停”，不做“批”。

### M3 核心体验

**目标**：论文从选题到定稿可以对话推进；开发交付从“能跑”升级为“可复核”；手机从“看”升级为“有限参与”。

**交付**

1. **文档/论文：七阶段与 0→1 对话**
   - 项目类型 `thesis / report` 政策入口，`resume` 类型在 M4 接入；论文旧路由作为兼容层保留。
   - 七阶段：`topic / sources / outline / research / drafting / revision / final`。
   - 三层状态：阶段、readiness（`not_started / gathering / needs_user / ready_for_review / accepted / needs_changes`）、artifact 状态。
   - 阶段事件 append-only；用户确认绑定内容哈希；上游变化把受影响的确认标为 stale。
   - 主动澄清：每轮 1–3 个实质问题，带默认动作和“暂不确定”；用户只给写作/选题/字数要求也能启动。
   - 分段草稿：按章节产出；AI 草稿标记；作者确认/修改/驳回；支持从已有稿直接进入修改阶段。
   - 多格式：新建报告用 Markdown 主控源（简历在 M4 复用）；已有论文保持 DOCX 原件做定点修改；新建论文草稿从模板 DOCX 或 IR 生成（源格式在 M3 实现前定稿）；导出 DOCX/PDF；每类格式有独立排版规则与保真报告。
2. **开发：CAP-04 证据包 + CAP-07 本地/服务器可比**
   - 主张组织为：结论、代码基线、diff、验证前后状态、环境 manifest、人工决策、未证明事项。
   - 确定性层（环境准备、测试、静态/契约检查、证据收集）不依赖模型即可在指定环境重跑；模型与提示版本只用于解释差异。
   - 同一验证清单在本地与容器运行后输出环境差异表：OS/arch、隔离、网络、镜像 digest、运行时/工具版本、检索后端；明确“哪些结论可比、哪些不可比”。
3. **远程：审批/继续/有限指令**
   - `approval.list` / `approval.decide` / `run.resume` / `answer.select`；自然语言追加指令放到后续，且仍由本地解析与权限审查。
   - 审批绑定动作哈希、单次使用、≤5 分钟过期；高风险操作远程只能拒绝/查看，不能批准。
   - 命令信封含 `command_id / device_id / type / action_hash / args_ciphertext / issued_at / expires_at / nonce / signature`；命令 `expires_at` ≤60 秒；本地验签、验时、防重放。
4. **文案：持续检查**
   - 词表与禁用主张进入 CI；新增用户可见文案必须过检查。
   - 论文对话中的模板化摘要、重复提醒、机械过渡语清理。

**验收**

- [ ] 论文完成“选题 → 来源 → 提纲 → 研究 → 起草 → 修改 → 定稿”，中途可回退；解析失败不丢阶段；过期确认可见。
- [ ] 用户只给要求（可选的选题方向/字数/写作要求）即可启动；Agent 每轮 1–3 个问题；不出现无人参与的整篇提交稿。
- [ ] AI 草稿有标识；作者确认绑定内容哈希；上游改动后受影响确认标 stale；导出前提示未确认项。
- [ ] 第三方按证据包独立重跑，不读会话也能判断通过/失败；删除或篡改产物会被校验发现；失败和未覆盖项不被汇总页隐藏。
- [ ] 本地与容器同一清单结果可并排比较，差异齐全；本地检索缺 embedding 时不能把回答差异归因于代码。
- [ ] 远程审批绑定动作哈希、单次、≤5 分钟；高风险操作远程批准被拒绝并审计；撤销设备后旧命令失效；离线恢复不重放。
- [ ] 文案 CI 检查通过。

**不做**：简历、跨仓库、代码→文档、排版优化。M3 的论文阶段是“参与式辅助”，不是“一键成稿”。

### M4 扩展人群

**目标**：让零经验学生与技术岗都能用真实事实做出岗位版本；让多仓库变更从“检索”升级为“影响报告”；让微信成为可选入口而非依赖。

**交付**

1. **文档/简历：简历 MVP**
   - 数据模型：Profile（主档案）+ Facts（事实库）+ JobVersion（岗位版本）。
   - 事实状态：`self_reported / evidence_linked / needs_confirmation / excluded`；无证据数字必须询问或拦截。
   - STAR 访谈：针对零经验学生（课程项目、社团、实习、竞赛）与技术岗（项目、开源、性能、故障）使用不同提问模板。
   - JD 快照：用户粘贴/导入 JD；一岗一版；岗位版本只引用事实库中的真实事实。
   - 一个可访问基线模板；DOCX/PDF/文本预览；ATS 兼容检查只报告工具看到的问题，不承诺通过率。
2. **开发：CAP-05 跨仓库影响报告**
   - 用户选择多个授权仓库及各自基线 commit；基于服务/契约/包依赖和符号引用给出受影响仓库、接口、测试和未知项。
   - 为每个仓库输出独立验证任务与变更提案；不把多仓库改动合成一个不透明补丁。
   - 静态分析局限随结果展示；动态导入/运行时依赖必须标“未覆盖”；无授权仓库绝不进入检索或报告；跨仓库写入禁止或走单独授权。
3. **远程：可选微信/企微适配 + PWA 完善**
   - 微信只作为“扫一扫打开 HTTPS 工作台”的入口；可选认证服务号只做脱敏通知；企业微信自建应用只做企业内部可选通道。
   - 个人订阅号不作为控制面；不要求用户注册公众号；不通过微信/企微传密钥、源码、完整日志。
   - PWA 完善：系统浏览器打开、通知权限引导、弱网/断网状态、设备管理。
4. **文案：文档与产品同步**
   - `/guide` 增加文档工作区、论文阶段、简历、远程工作台章节；宣传页不提前写未上线能力。

**验收**

- [ ] 零经验学生与技术岗各用真实项目生成两个岗位版本；无证据数字被拦截/询问；预览可读；无编造事实。
- [ ] 至少两个样例仓库的契约变更能列出双向影响；故意加入动态导入/运行时依赖时标“未覆盖”；无授权仓库不进入报告。
- [ ] 跨仓库只读报告与分仓提案可用；跨仓库写入被禁止或走单独授权。
- [ ] 微信/企微适配可关闭；通知只含脱敏内容；个人订阅号不作为前置条件。
- [ ] 简历不承诺 ATS 通过率；不提供自动海投。
- [ ] `/guide` 与实际上线能力一致。

**不做**：模板市场、自动投递、职位抓取平台、ATS 通过率承诺、跨仓库无人值守写入。

### M5 证据闭环与生态

**目标**：把“代码→文档”的断言链打通；把排版优化/转换做成文档工作区的通用能力；按验证结果决定是否做独立移动端。

**交付**

1. **开发：CAP-06 代码→文档/作品集断言证据链**
   - 技术说明或作品集中的每项陈述标注 `代码事实 / 实测结果 / 人工说明 / 未验证`。
   - 分别绑定 commit+行号、验证运行与原始产物、作者说明或空证据。
   - commit 或代码变化后自动标记失效，只重验受影响断言。
   - AI 生成说明必须与人的贡献说明区分。
2. **文档：排版优化/转换**
   - 作为文档工作区的工具/项目类型，与简历共用 IR、预览、版本、导出。
   - 支持常见转换：MD→DOCX/PDF、DOCX→PDF、DOCX 定点排版修复；明确不支持 PDF→DOCX 任意反向编辑。
   - 每次转换输出保真报告：保留了什么、改了什么、丢了什么、哪些对象不支持。
   - 可选 Typst/LaTeX 后端、OCR、模板包；每个扩展有独立保真/隐私验收。
3. **远程：独立移动端（条件触发）**
   - 仅当 PWA 在目标手机/微信内置浏览器上的通知、后台、体验不达标时，才做独立 App；否则不做。
   - 多设备管理、设备丢失演练、通知偏好。
4. **文案：持续复盘**
   - 每季度复核宣传页、`/guide`、产品文案与真实能力；删除不再成立的承诺。

**验收**

- [ ] 引用行号漂移、证据产物丢失、数字无法在结构化结果找到时，导出被阻止或显著标错。
- [ ] 删除被引用的实现后文档不能继续显示“已核实”；AI 生成说明与人的贡献说明可区分。
- [ ] 每种转换格式有独立样例与保真报告；没有测试的格式不得标“支持”。
- [ ] 独立移动端有明确的 PWA 不达标证据；否则不做。
- [ ] 文案与能力一致。

**不做**：通用 WYSIWYG Office 编辑器、PDF 任意反向编辑、全场景 OCR、批注/修订全兼容、云协作、模板数量竞赛。

## 5. 工作流细节

### 5.1 开发 Agent：对齐与差异

**对齐主流的顺序**

1. **M1 事实层**：统一验证结果 + 隔离披露。没有它，PR、证据包、文档断言都会各自造格式。
2. **M2 交付闭环**：draft PR、CI、评审、按评论修订。外部操作明确授权；不做自动合并。
3. **M3 可复核**：证据包 + 本地/服务器可比。这是 Nova 与“有日志的 Agent”拉开差距的地方。
4. **M4 跨仓库**：先只读影响报告与分仓提案，不做跨仓库写入。
5. **M5 代码→文档**：复用证据包，让文档中的能力/性能/结果陈述回到代码与运行产物。

**差异化的四件事**

- **主张级证据包**：以“主张”而不是工具调用组织交付；保留反例、失败、未覆盖项和人工决策。
- **跨仓库影响**：以用户授权的多个仓库为工程边界，给出依赖证据与分仓验证。
- **本地/服务器可比**：不假装无隔离主机与容器相同；记录差异，给出可比性结论。
- **代码→文档断言链**：文档中的每项陈述可回到 commit、行号、验证运行或人工说明。

**明确不做**：自动合并、自动发布、无人值守跨仓库写入、承诺模型输出完全一致、把自动检查称为合规认证、生成无证据的性能/用户数字。

### 5.2 文档工作区：一个引擎，三种项目

**项目类型**

| 类型 | 主控源 | 写作方式 | 参与边界 |
|---|---|---|---|
| 论文 | 已有 DOCX 保持原件；新建草稿从模板 DOCX 或 IR 生成（源格式 M3 前定稿） | 七阶段对话推进；分段草稿 + 作者确认 | 作者实质参与；不提供无人参与的整篇提交稿 |
| 报告 | Markdown | 可从需求到完整起草 | 可完整起草；AI 草稿标识 |
| 简历 | Markdown/结构化事实 | 事实库 + JD 对齐 + 一岗一版 | 只重组真实事实；不编造 |

**文档引擎**

- **IR + 变更集**：段落、标题、列表、表格、图片、页眉页脚、分节、样式引用；变更以“操作 + 目标 + 前后哈希”表达。
- **两条编辑路径**：
  - 新建报告/简历/论文草稿：Markdown 主控源 → 导出 DOCX/PDF。
  - 已有论文：保留 DOCX 原件，只做定点 OOXML 修改；不把 DOCX 往返成 Markdown。
- **渲染/导出**：Pandoc 随桌面端内置；LibreOffice 首次 PDF 预览/导出时按需下载固定版本、校验哈希；离线时 DOCX/Markdown 可用，PDF 明确降级。
- **保真报告**：每次导出/转换说明保留、修改、丢失、不支持的内容；不宣称无损往返。
- **本地目录**：`source/ manuscripts/ assets/ exports/ .nova/{project.json,snapshots,changes}`；哈希校验；原子写；冲突检测；版本历史；不静默覆盖。

**论文七阶段**

```text
topic → sources → outline → research → drafting → revision → final
  ↑        ↑         ↑          ↑           ↑          ↑
  └────────┴─────────┴──────────┴───────────┴──────────┘  可回退
```

- 每阶段有 readiness 与 artifact 状态；阶段事件 append-only。
- 用户确认绑定内容哈希；上游变化使受影响确认 stale。
- 主动澄清每轮 1–3 个问题，带默认动作和“暂不确定”；不一次问十个问题。
- 从已有稿进入时，可直接跳到 `revision`，不强迫从选题重走。

**简历**

- Profile / Facts / JobVersion 分离；事实状态可审计。
- STAR 访谈按人群使用不同模板；零经验学生与技术岗共用事实库与一岗一版。
- JD 快照保存岗位要求；岗位版本只引用事实库中的真实事实。
- ATS 兼容检查报告“工具看到的问题”，不承诺通过率；首期只提供一个可访问基线模板。

**排版优化/转换**

- 放在 M5，作为文档工作区的通用工具/项目类型，与简历共用 IR、预览、版本、导出。
- 先做 MD→DOCX/PDF、DOCX→PDF、DOCX 定点排版修复；不做 PDF→DOCX 任意反向编辑。
- 每次转换有保真报告与不支持清单；没有测试的格式不标“支持”。

### 5.3 远程工作台：看、停、批

**架构**

```text
手机 H5/PWA ──HTTPS/WSS（应用层 E2EE）──▶ 受控中继 ──◀── 本地 Agent
  设备私钥                                  密文路由        仅出站 mTLS WSS
  进度/审批/停止                            设备注册        权限/审计/脱敏
```

**绑定**

1. 桌面生成一次性 token（≥128 位）+ 临时密钥对 + 5 分钟 TTL；中继只存 token 哈希。
2. 二维码内容是 Nova 自己的 HTTPS 链接，秘密放 URL fragment，不进服务器 query 日志。
3. 手机生成设备密钥对；公钥和 token 提交中继。
4. 桌面与手机显示同一短验证串（SAS），用户核对后在本地确认设备名称与权限范围。
5. 绑定成功 token 立即失效；重复使用、过期、SAS 不一致都拒绝；失败限流并告警。

**有限意图**

| 意图 | 说明 | 风险 |
|---|---|---|
| `status.get` | 只读进度 | 低 |
| `run.stop` | 停止当前任务；最高优先级、始终可用、幂等 | 低 |
| `approval.list` | 待审批列表 | 低 |
| `approval.decide` | 同意/拒绝；绑定动作哈希、单次、≤5 分钟 | 中 |
| `run.resume` | 仅在本地策略允许时继续已暂停任务 | 中 |
| `answer.select` | 对本地已提出的选择题作答 | 中 |
| 自然语言追加指令 | 第二阶段；本地解析、权限审查，不直接进 shell | 中 |

**高风险（远程只能拒绝/查看，不能批准）**：删除文件、执行任意命令、修改系统配置、访问密钥/凭据、外发源码、支付类操作。

**微信/企微边界**

- 个人订阅号不能认证，不能用参数二维码、网页授权、客服消息、模板/订阅通知；不能作为控制面。
- 认证服务号只做可选通知适配；企业微信自建应用只做企业内部可选通道；群机器人只做单向通知。
- 微信/企微消息不是 E2EE；只发任务 ID、脱敏状态、一次性链接，不发密钥、源码、完整日志。
- 默认方案不依赖任何公众号：普通 HTTPS 二维码/链接 + passkey/邮件 magic link + 应用内/Web Push/邮件通知。

### 5.4 文案：说人话，说真话

**产品语气**

- 具体、平实、主动语态；描述“做什么、会发生什么”，不描述“AI 多聪明”。
- 一个动作在全流程用同一个词：按钮“发布”，toast 就说“已发布”。
- 错误说明发生了什么、怎么修；空状态给下一步，不卖萌。
- 保留必要的“AI 草稿”“AI 使用声明”“未验证”“不支持”。

**清理范围**

- 宣传页、`/guide`、下载页、登录页。
- 论文对话、写作面板、Builder 对话、Agent 系统提示、子代理提示。
- 审批卡、错误/空状态、通知、导出报告。

**禁用/慎用**

| 类型 | 例子 | 处理 |
|---|---|---|
| 拟人化空话 | “让 AI 理解你的需求”“AI 会思考” | 改成具体行为：“读取项目文件并给出修改建议” |
| 夸大形容词 | “智能、全面、轻松、无缝、一键搞定” | 删除或换成可验证的事实 |
| 机械摘要 | 每轮重复“已完成以下步骤” | 只在与上轮有变化时总结 |
| 重复提醒 | 每段都提醒“请检查 AI 内容” | 在关键节点提示一次，保留声明 |
| 不可验证承诺 | “降低 AI 率”“保证通过”“ATS 友好” | 删除；改为“检查了什么、没检查什么” |
| 伪造社会证明 | 编造用户数、通过率、合作学校 | 删除；只写真实可核验的信息 |

## 6. 质量门与验收方式

### 6.1 原则

- **证据优先于声明**：每个里程碑的“完成”必须有实际命令输出、样例产物或人工验证记录；“代码存在”不算完成。
- **失败要可见**：失败、未运行、跳过、工具缺失、未覆盖必须出现在结果里，不能被汇总页隐藏。
- **不静默降级**：组件缺失、格式不支持、网络不可用、远程离线，都要明确提示与可选动作。
- **不拿审批替代隔离/测试**：审批是权限控制，不是安全隔离，也不是验证。

### 6.2 质量门

| 门 | 时点 | 必须通过 |
|---|---|---|
| G0 | M1 结束 | CAP-01/02 样例；文档 IR 样例；远程 schema；文案词表 |
| G1 | M2 结束 | PR 闭环；报告导出/冲突/回退；远程绑定/进度/通知/停止；文案首批 |
| G2 | M3 结束 | 论文七阶段；证据包重跑；本地/容器可比；远程审批；文案 CI |
| G3 | M4 结束 | 简历两岗两版；跨仓库影响报告；微信可选适配；文档同步 |
| G4 | M5 结束 | 代码→文档断言链；转换保真报告；独立移动端决策；文案复盘 |

### 6.3 测试类型

| 类型 | 用途 | 例子 |
|---|---|---|
| 单元/集成 | 结果模型、权限、IR、阶段转移 | 失败/跳过/未运行分类；阶段回退；确认 stale |
| 黄金样例 | 开发交付、文档导出 | 固定仓库的红→绿；固定 DOCX 的解析/导出 |
| 保真测试集 | 文档格式 | DOCX/MD/PDF 样例的保留/丢失/不支持清单 |
| 安全测试 | 远程、权限、密钥 | token 重用、SAS 错误、命令重放、高风险远程批准 |
| 端到端 | 用户场景 | 报告从需求到导出；论文选题到定稿；手机看进度并停止 |
| 真机测试 | 远程 | Android/iPhone、微信内置浏览器、系统浏览器、弱网/断网 |

### 6.4 发布检查

- [ ] 测试通过；失败/跳过有说明。
- [ ] 文案与实际能力一致；未上线能力不写成“已有”。
- [ ] 文档更新（`/guide`、README、相关设计文档）。
- [ ] 无新增公网监听；无密钥/令牌进入日志或导出。
- [ ] 回滚方案明确；数据库迁移可回退。
- [ ] 审计事件齐全；远程变更可在本地与中继对上。

## 7. 动态调整规则

路线图允许调整，但必须留下记录；不允许“做着做着目标变了，但文档没变”。

### 7.1 调整流程

1. **写清原因**：用户反馈、技术阻塞、验证结果、成本/容量、安全要求。
2. **列出影响**：哪些能力、里程碑、验收条件、对外文案受影响。
3. **给替代方案**：至少一个更小的可验收切片，说明为什么它仍能验证目标。
4. **更新本文**：修改对应章节；在 §8 决策记录追加一条（日期、决定、原因、影响、新验收）。
5. **通知一致**：宣传页、`/guide`、README 与实际能力同步；不提前承诺。

### 7.2 调整边界

- 可以调整**顺序、切片大小、实现方式、时间**。
- 不可以静默删除**红线**（§1）或降低**验收条件**；如果必须降级，要显式写成“暂不支持”，并保留未完成项。
- 如果某阶段验收失败：先修复或缩 scope；不得把失败项藏到“后续优化”。
- 如果新方案能复用现有 Agent 循环/权限/Job/证据，优先复用；不要为了赶进度另建一套。
- 如果某能力连续两个阶段没有真实用户验证，暂停扩展，先做用户测试。

### 7.3 复杂度预算

- **一个文档引擎**，不为论文/报告/简历各写一套。
- **一个证据 schema**，开发交付、文档断言、远程进度共用。
- **一个远程意图模型**，不允许各入口自定义命令。
- **一个权限引擎**，远程只是增加审批因子。
- 新依赖（Pandoc/LibreOffice/Typst/LaTeX/OCR）必须有版本锁定、哈希校验、失败降级和保真测试。

## 9. 风险与待验证假设

| 风险/假设 | 影响 | 验证方式 | 缓解 |
|---|---|---|---|
| 学生是否愿意为“可复核的项目证据/作品集”投入时间 | 影响 M5 价值 | 小规模真实项目试用 | 先做证据包，不先做模板市场 |
| 跨仓库影响是否足够高频 | 影响 M4 投入 | 访谈 + 真实仓库试用 | 先只读报告，低成本验证 |
| 用户是否愿意提供锁文件/容器信息 | 影响可复现性 | 任务测试 | 提供“最低可复现”路径，不强制 |
| 证据包是否比 GitHub 会话/PR 审查更有感知价值 | 影响差异化 | 对比试用 | 强调失败/未覆盖/环境差异 |
| Pandoc/LibreOffice 打包与离线/代理环境 | 影响 M2 文档底座 | Windows/macOS/Linux 实测 | 版本锁定、哈希、显式降级、离线包 |
| Web Push/PWA 在微信内置浏览器可用性 | 影响 M2 通知 | 真机实测 | 提供系统浏览器打开；邮件兜底 |
| 大陆公网中继 ICP/备案 | 影响 M2 远程 | 接入商/备案确认 | 自有 VPS + 已备案域名；或先局域网/受控环境验证 |
| 简历 PDF 可访问性标准 | 影响 M4 验收 | 选定标准 + 工具检查 | 不以“ATS 友好”代替无障碍 |
| 已有论文用户入口偏好（DOCX vs 选题） | 影响 M3 默认顺序 | 访谈/任务测试 | 两个入口都保留，默认后定 |
