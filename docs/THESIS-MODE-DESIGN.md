# Nova Agent 论文模式设计（开源版 v1.1）

> 日期：2026-11-20  
> 调研依据：[`docs/research/2026-11-20-thesis-assistant-market.md`](2026-11-20-thesis-assistant-market.md)（122 条来源，A/B/C/D 分级）  
> 开发计划：[`docs/THESIS-MODE-ROADMAP.md`](THESIS-MODE-ROADMAP.md)（任务分解、里程碑、质量门、风险）  
> 性质：单一端、开源、本地优先的产品设计。开发模式保持不变，新增可切换的「论文模式」；核心功能免费，用户自带模型（BYOK），不强制账号、不上传论文、默认无遥测。  
> 结论：**不做一个新的论文软件，在 Nova 桌面端里增加一个论文模式；先做开源免费版，后续可选托管/院系版，但不给核心功能加付费墙。**

---

## 0. 一句话

**Nova 论文模式 = 开源、本地优先的论文体检与修复：格式、引用、AI 使用，一次做对；模型用你自己的。**

它不写论文、不润色、不降重、不降 AIGC；它打开论文，逐条检查、给出证据、协助修复、导出可提交的定稿包。论文默认不出本机，模型调用走用户自己配置的 Key 或本地模型。

## 1. 为什么是「模式」，不是「端」

| 选项 | 问题 | 结论 |
|---|---|---|
| 新做一个论文 Web 工作台 | 学生已经在 Word/WPS 写完；上传/下载/格式转换是额外摩擦；2C2G 服务器扛不住文档解析；还要 ICP | 不做 |
| 新做一个 Word/WPS 插件 | 插件沙箱拿不到本地文件/进程/PDF 全文，Nova 的沙箱与证据链被削掉；且是第二个入口 | MVP 不做；未来可作为同一安装包里的可选侧边栏 |
| 新做一个独立桌面 App | 与 Nova 现有桌面端重复；两个产品、两套更新、两套账号 | 不做 |
| **在 Nova 里加一个论文模式** | 复用桌面端、本地运行时、对话/工作台/证据 UI、BYOK、项目模型 | **做这个** |

论文模式与开发模式共享同一个壳：

```text
Nova Agent
├─ 开发模式（现有，不动）
│   项目 = 代码仓库；证据 = 文件:行号；执行 = 沙箱
└─ 论文模式（新增）
    项目 = 论文/毕设；证据 = 页码/段落:原文；执行 = 文档解析 + 规则 + 引用核验
```

**一个安装包、一个界面；本地模式无需账号，自托管才需要账号。** 用户只是在顶部切换「开发 / 论文」。

这也是对「现在这个模式是办公辅助」的延续：同一个助手，换一种专业视角。开发模式打开仓库，论文模式打开论文；开发模式跑测试，论文模式跑合规检查；开发模式给 `文件:行号`，论文模式给 `页码/段落:原文`。交互不变，工具变了。

开源版的分发形态有三种，但仍是同一个产品：

- **Windows 桌面安装包**：普通学生用，双击安装，本地运行；
- **Docker Compose 自托管**：有服务器/实验室的用户用，浏览器访问；
- **源码运行**：开发者/贡献者用，`pip`/`npm` 起本地前后端。

三种形态共用同一套前端、后端和论文模式，不分裂成三个产品。

## 2. 市场依据（为什么现在做）

1. 2027 届高校毕业生预计 **1299 万**；按本专科 85%、研究生 95% 估算，论文/毕设写作者约 **1050–1100 万**（调研 §2）。
2. **2026 是换版窗口**：GB/T 7713.1—2025《学位论文编写规则》2026-02-01 实施，GB/T 7714—2025《参考文献著录规则》2026-07-01 实施；中国科大等已在新模板中加入 AI 使用声明（调研 §0、§6）。
3. **格式是答辩季最常被吐槽的非研究性问题**；打印店排版 28 元起，WPS 大会员 188 元/年（调研 §0）。
4. **引用是高风险环节**：55.03% 受访学生遇到过参考文献错误；河北大学、港大出现 AI 虚构引用案例（调研 §0、§6）。
5. **AIGC 检测不可靠**：同一篇 100% AI 论文在三平台检出 99.9%/49.97%/24.68%；原创论文也可能被误判（调研 §6.3）。所以做「披露/解释/过程留痕」，不做「降 AI 率」。
6. **学生已经为论文结果付过钱**：查重支出 100–199 元是最大区间；62.7% 买过工具服务；但通用 AI 写作已被免费工具覆盖（调研 §7）。

**结论：需求不是「帮我写」，而是「帮我交得出去」。**

这些数据只证明需求存在，不代表本产品要收费。开源版的核心检查功能免费；用户只承担自己的模型/API 成本（BYOK，或本地 Ollama/vLLM 零 API 费）。

## 3. 用户与场景

### 3.1 首批用户

| 人群 | 规模 | 场景 | 为什么用 |
|---|---|---|---|
| 人文社科本科（大四） | 最大 | 定稿前 72 小时：格式、目录、页码、参考文献 | 一次过、不被退回、不因格式延误答辩 |
| 人文社科硕士（研二/研三） | 中 | 盲审前：引用核验、格式、AI 声明 | 盲审不被抓假文献、不被认定学术不端 |
| 所有本科/硕士 | 最大 | 学校要求 AI 使用声明 | 知道该披露什么、怎么披露 |
| CS/理工本科/硕士 | 中 | 毕设代码/数据复现、图表证据 | 代码能跑、结果能复现、答辩讲得清 |

### 3.2 不服务（首期）

- 博士高定制论文（引用量太大、学科差异太大）；
- 艺术/设计作品集、医学统计、法学引注（需要专门模板）；
- 导师/院系的协作与审批（B 端，6–12 个月后）；
- 任何代写、降重、降 AIGC、伪造引用需求。

### 3.3 使用时机

- 主峰：**2–6 月**（初稿、查重、盲审、答辩）；3–5 月最集中。
- 次峰：9–12 月（选题、开题）。
- 产品必须适应「毕业季集中使用」的节奏；开源版不做订阅锁，但可以在毕业季做集中推广和模板更新。

## 4. 产品结构

```text
┌────────────────────────────────────────────────────────────┐
│  Nova Agent            [开发] [论文]        模型 · 本机 · 账号 │
├──────────────┬──────────────────────────────┬──────────────┤
│ 论文项目      │  对话 + 体检工作台              │ 证据 / 引用 / 版本 │
│              │                              │              │
│ ▾ 我的毕业论文 │  ┌─ 体检概览 ─────────────┐   │  规则条款      │
│   ├ 封面      │  │ 阻断 3 · 警告 12 · 建议 8 │   │  文档位置      │
│   ├ 摘要      │  └────────────────────────┘   │  当前值/建议值  │
│   ├ 第一章    │  ┌─ 问题列表 ─────────────┐   │  来源/置信度    │
│   ├ 第二章    │  │ [阻断] 页码格式不一致   │   │              │
│   ├ 第三章    │  │ [警告] 图 3-2 题注缺失  │   │  引用证据      │
│   ├ 参考文献   │  │ [警告] 参考文献 [12]... │   │  页码/原文     │
│   └ 致谢      │  └────────────────────────┘   │              │
│              │  [预览] [应用] [撤销] [导出]     │              │
└──────────────┴──────────────────────────────┴──────────────┘
```

- **左**：论文项目 + 文档结构树（章节、图表、参考文献、附件）。
- **中**：对话仍然在，但主界面是「体检工作台」；用户可以直接点问题，也可以对 Agent 说「只看第三章」。
- **右**：选中问题时显示证据卡；选中引用时显示核验来源；顶部可切换版本。
- **底/右上**：导出定稿包。

## 5. 端到端体验（定稿前 72 小时）

1. **新建论文项目**：填学校/学院/学位/专业；选学校模板（或先用国标通用规则）。
2. **导入 docx**：本地读取；原文件不动，生成工作副本；自动备份。
3. **一键体检**（2–5 分钟）：格式 + 引用 + AI 声明缺失项；SSE 显示进度。
4. **看问题清单**：按「阻断/警告/建议」和章节排序；每条有位置、规则、当前值、建议值、依据。
5. **逐条修复**：预览 → 应用 → 撤销；只改格式/结构，不改正文内容；复杂域（目录、交叉引用）提示「在 Word 中按 F9 更新」。
6. **引用核验**：文内引用 ↔ 文末文献；元数据；重复/缺失/顺序；可选上传 PDF 做全文核验。
7. **AI 使用声明**：导入/记录工具、版本、用途、环节、提示词；生成声明 + 脚注 + 答辩 Q&A。
8. **导出定稿包**：修复后的 docx + 体检报告 + 引用清单 + AI 声明 + 提交说明。
9. **复检**：改完再扫一遍，直到「阻断 = 0」；报告记录两次扫描的差异。

## 6. 功能规格

### 6.1 格式体检

**检查范围**（MVP）：

| 类别 | 检查项 | 修复方式 |
|---|---|---|
| 页面 | 纸张、页边距、装订线、页眉页脚距离、行距、段前段后 | 自动/建议 |
| 分节 | 封面/摘要/目录/正文/参考文献/致谢分节；页码格式（罗马/阿拉伯） | 自动 |
| 页眉页脚 | 内容、奇偶页、首页不同、与章节标题一致 | 自动/建议 |
| 标题 | 一/二/三级标题的字体、字号、加粗、对齐、缩进、编号、段前段后 | 自动 |
| 目录 | 自动目录、页码对应、域是否更新 | 提示 + Word F9 |
| 图表 | 题注位置、编号连续、图题/表题字体、三线表、跨页表头、交叉引用 | 自动/建议 |
| 公式 | 编号、对齐、OMML | 建议 |
| 参考文献 | GB/T 7714—2025 条目格式、作者、文献类型、标点、DOI、排序 | 自动/建议 |
| 摘要/关键词 | 字数、关键词数量、分隔符、英文摘要 | 建议 |
| 盲审版 | 隐去姓名/学号/导师/学校；删除致谢（可配置） | 自动 |
| 提交项 | 承诺书、查重报告、附录、字数 | 提示 |

**问题卡片的统一结构**：

```text
[阻断] 页码格式不一致
位置：正文 · 第 3 节 · 页脚
当前：1, 2, 3 ...
应为：I, II, III ...（前置部分）；1, 2, 3 ...（正文）
依据：XX大学 2026 届模板 §4.2；GB/T 7713.1—2025 §6.3
修复：将第 1–3 节页码改为罗马数字（只影响页脚，不改正文）
[预览] [应用] [忽略]
```

**修复原则**：

- 只做**可逆的、结构化的**修改；不重排全文、不改正文文字。
- 每次修改前自动备份；应用后可撤销；支持「全部撤销」。
- 复杂域（目录、交叉引用、题注编号）可能需要在 Word 中更新域；产品提示步骤，不假装已更新。
- 误报可「忽略」，忽略记录进入报告（让导师/学院看到你确认过）。

**页面级检查**：

- 结构级检查不依赖渲染，MVP 必做。
- 页面级检查（实际页码、目录页码、图表跨页、孤行寡行）依赖 LibreOffice/Word 渲染；检测到就启用，检测不到就在报告中标注「未做页面级校验」。
- 不承诺「和打印店完全一致」；只承诺「规则可解释、问题可定位」。

### 6.2 引用核验

分三层，按实现复杂度与依赖开放：

| 层级 | 做什么 | 输出 | 开源版实现 |
|---|---|---|---|
| L1 对应检查 | 抽取文内引用 + 文末文献；编号/作者-年份匹配；重复、缺失、顺序 | 对应关系表 | 本地规则，无需模型/API |
| L2 元数据核验 | DOI/Crossref/OpenAlex；标题/作者/期刊/年份/卷期/页码；撤稿标记 | 每条状态 + 证据链接 | 公共 API，免费；结果缓存 30 天 |
| L3 全文核验 | 用户上传 PDF；定位引文页码/原文；判断支持/部分支持/不支持/不确定 | 页码 + 原文 + 置信度 | 用户自带 PDF + BYOK 模型；token 成本由用户承担 |

> 开源版三层都可用，没有功能锁；L3 的边际成本是用户自己的模型 token，不是产品收费点。

**状态定义**（必须可解释）：

- `已核实`：元数据与来源一致；
- `部分匹配`：标题/作者匹配，但年份/卷期/页码有差异；
- `信息不符`：来源存在，但关键字段不一致；
- `未找到`：公开源未检索到，不等于伪造；
- `需人工确认`：中文文献/无 DOI/多版本；
- `疑似撤稿`：来源标记撤稿。

**原则**：

- 没有来源证据，绝不标「已核实」。
- 中文文献优先用户自带 PDF；公开元数据其次；不爬知网/维普/万方。
- 全文核验显示「支持/部分支持/不支持/不确定」+ 页码 + 原文；最终由用户确认。
- 报告里写清「核验范围/来源/时间/局限」，不写「包过」。

### 6.3 AI 使用披露

- **本地记录**：工具、版本、用途、环节、提示词、生成内容、用户修改、时间。
- **导入**：Nova 自己的对话可自动记录；其他工具（ChatGPT/Kimi/豆包等）可粘贴/导入为文本。
- **学校模板**：按学校要求生成声明、脚注、答辩 Q&A（复旦/川大/人大/江南/中国科大等，配置化）。
- **诚实原则**：声明内容由用户确认；产品只做整理和格式化，不代填虚假内容。
- **不做**：AIGC 检测、降 AI 率、绕过检测、伪造「人类写作」证据。

**为什么这是功能而不是独立产品**：政策强、单独使用频率低；它应该作为开源版的标准模块默认包含，而不是单独做一个入口。

### 6.4 学校政策感知

- 每所学校一个 `template.json`：模板版本、页面设置、样式、章节要求、参考文献格式、盲审规则、AI 政策、AIGC 阈值。
- 规则带 `source`（学校通知/模板/国标）和 `version`；报告里显示规则来源。
- 用户操作前提示：「你学校不允许 AI 润色，此功能不可用」；不默认提供违规功能。
- MVP 覆盖 10–20 所学校；首批 3 所跑通；后续靠社区 PR、学校用户和模板贡献者共建。

### 6.5 报告与导出

**定稿包**：

```text
我的毕业论文_定稿包/
├─ 我的毕业论文_修复版.docx
├─ 论文体检报告.docx / .html（可打印 PDF）
├─ 引用核验清单.csv
├─ AI使用声明.docx
├─ 修改记录.json（每条问题：规则/位置/前后值/时间）
└─ 提交说明.md（还有什么需要人工确认）
```

报告结构：

1. 封面：学校/学院/学位/模板版本/扫描时间/工具版本；
2. 总览：阻断/警告/建议数量；各章节通过率；
3. 问题清单：位置、规则、当前值、建议值、依据、修复状态；
4. 引用核验：逐条状态 + 证据链接/页码；
5. AI 使用声明；
6. 局限：未检查项、需人工确认项、页面级校验是否完成；
7. 复检差异（如果扫描多次）。

### 6.6 版本与回滚

- 每次导入/扫描/修复生成版本；段落级 diff；可恢复。
- 原文件永不覆盖；输出到新文件；工作副本放项目目录。
- 本地 SQLite/现有存储记录问题与修改；可导出 JSON 审计。

### 6.7 毕设项目（第二阶段，同一个模式）

- 项目类型从「论文」扩展到「毕设」：代码仓库 + 数据 + 论文。
- 能力：环境锁定、依赖安装、沙箱运行测试、复现 3 个关键图表/表格、生成「图表/表格 → 代码行/数据行 → 运行日志」证据附录。
- 复用：沙箱、仓库索引、红-绿修复、影响分析、`文件:行号` 证据。
- 缺口：沙箱目前只返回 stdout/stderr，需要增加 artifact 收集（输出目录/zip）。
- 定位：不生成完整项目、不代写论文；只做复现、验证、解释。
- 成本：开源版免费；用户只承担自己的模型/算力成本。

## 7. 与现有 Nova 的映射

| 现有能力 | 论文模式怎么用 | 缺口 |
|---|---|---|
| Windows 桌面端 + 本地运行时 | 本地读 docx/PDF；不上传；2C2G 不参与重计算 | 无 |
| 对话 + SSE + 可恢复 turn | 体检进度、逐条解释、复检 | 无 |
| 工作台三栏 + 证据 UI | 问题列表 + 证据卡 + 版本 | 新增论文工作台组件 |
| `文件:行号` 证据链 | 改成 `页码/段落:原文` | 新的定位/展示组件 |
| PDF 解析（pypdf） | 参考文献 PDF、全文核验 | 需要版面/页码级解析（pdfplumber） |
| RAG/混合检索 | 在 PDF 中找引文原句 | 需要按页/段落切分与定位 |
| 沙箱执行 | 毕设复现 | 需要 artifact 收集 |
| BYOK/多模型 | 用户自选模型；成本可控 | 无 |
| 多用户/配额/审计 | 未来院系版 | 需要 B 端权限模型 |
| Skills | 学校模板/检查规则包 | 需要规则包格式 |
| 交付报告 | 论文体检报告 | 新模板 |

**核心判断：Nova 的护城河不是「会写代码」，而是「可验证」。论文合规是同一护城河的第二应用。**

### 7.1 开源版的产品原则

1. **核心免费，无付费墙**：格式检查、引用 L1/L2、AI 声明、导出全部免费；不把「导出修复后的 docx」做成付费功能。
2. **BYOK，无供应商锁定**：用户用自己的 API Key；支持 OpenAI-compatible 自定义端点、Ollama、vLLM；没有 Key 也能跑本地规则（格式/L1）。
3. **本地优先，默认不上传**：论文、PDF、引用库留在本机；只有用户显式启用模型功能时，才把必要片段发到用户配置的模型端点。
4. **无强制账号，默认无遥测**：桌面本地模式不需要注册；不收集论文内容、不收集使用行为；如需崩溃报告，必须显式 opt-in。
5. **社区共建模板**：学校模板、规则包、引用适配器以 PR 形式贡献；模板只编码规则，不复制学校受版权保护的模板文件。
6. **可复现构建**：Release 提供校验和/签名；Docker 镜像固定版本；依赖锁定。
7. **后续商业化不反噬核心**：以后可以做托管服务、院系版、技术支持、定制模板；但核心开源版保持完整可用。

### 8.4 Agent 工具与技能

论文模式不是静态面板，Agent 仍可调用工具：

```text
thesis_scan(project_id, scope)                 # 触发体检
thesis_issue(issue_id)                        # 解释某条问题
thesis_preview_fix(issue_id)                  # 预览修复
thesis_apply_fix(issue_id)                    # 应用（需用户确认）
thesis_audit_citations(project_id, level)     # L1/L2/L3
thesis_disclosure(project_id)                 # 生成声明
thesis_export(project_id, kinds)              # 导出
```

学校模板/检查规则可作为 `SKILL.md` 规则包分发；但 MVP 先用内置 JSON，避免把规则引擎复杂化。

### 8.5 文档处理

- 解析：`python-docx` 处理高层结构；`lxml` 直接处理 OOXML（域、书签、题注、交叉引用、脚注、OMML）。
- 修改：只改目标 `run`/`paragraph`/`section` 属性；保留原有样式与编号；不重建文档。
- 预览：生成 before/after 文本片段 + 受影响段落列表；可选生成对比 docx。
- 备份：原文件 hash 校验；工作副本；失败可回滚。
- 安全：限制文件大小/解压后大小；XML 解析禁用外部实体；不执行宏；路径限定项目目录。

### 8.6 引用数据源

- 国际：Crossref REST API、OpenAlex API；DOI 优先；缓存 30 天。
- 中文：用户自带 PDF > 公开元数据 > 人工确认；不爬知网/维普/万方。
- 全文：`pdfplumber` 按页抽取文本；混合检索定位候选段落；LLM 判断支持度；显示页码 + 原文 + 置信度；用户确认。
- 准确率：元数据 ≥95%；全文精确率 ≥90%（人工抽检）；达不到就降级为「需人工确认」。

### 8.7 依赖与部署

新增后端依赖（版本在实现时锁定）：

```text
python-docx
lxml
pdfplumber
```

- `pypdf` 已有，保留用于快速文本抽取。
- PDF 报告：优先生成 docx/html；检测到 LibreOffice 时用 headless 转 PDF；否则让用户打印。
- 不引入富文本编辑器、PDF.js、Office.js；MVP 保持依赖窄。
- 桌面端：本地后端执行解析/规则；服务器只做账号/模型/授权；2C2G 不承担文档处理。
- 如果未来做 Word/WPS 侧边栏：同一安装包内可选组件，通过 localhost 调本地服务；仍是一个产品。
- 开源版默认不依赖作者的服务器：桌面端本地起后端；自托管用 Docker Compose；模型调用直连用户配置的 provider。只有可选的多用户/院系版才需要中心服务器。

### 8.8 安全与隐私

- 本地优先：论文默认不上传；服务器模式明确提示。
- 不训练：学生论文/引用 PDF 不进入训练集。
- 可删除：项目删除即删本地文件/索引/日志（保留审计除外）。
- 权限：项目目录限定；导出包不含未授权文件。
- 合规：用户协议明确禁止代写/降重/伪造引用；发现滥用可限制功能。
- 默认无遥测：不收集论文内容、路径、使用行为；崩溃报告必须显式 opt-in，且不含文档内容。
- 网络可见：设置页列出所有外联端点（用户配置的模型、Crossref/OpenAlex），支持「仅本地」模式。

## 11. 开源分发、社区与后续商业化

### 11.1 分发

- **GitHub Releases**：Windows 安装包、macOS/Linux 构建、SHA256 校验和；一键下载。
- **Docker Compose**：`docker compose up` 起自托管；适合实验室/宿舍服务器。
- **源码运行**：README 提供 `uv`/`pip` + `npm` 两条命令；贡献者用。
- **一键体验**：仓库内置 3 个脱敏样例论文 + 预期报告，用户不用先找论文就能看到效果。

### 11.2 上手路径（5 分钟）

1. 下载/启动 Nova；
2. 切到「论文」模式；
3. 导入样例 docx 或自己的论文；
4. 选学校模板（没有就先用国标通用规则）；
5. 点「体检」，看问题清单；
6. （可选）在设置里填自己的模型 Key；不填也能跑格式/L1。

**关键：没有 API Key 也能完成第一次体检。** 这是开源版和付费 SaaS 最大的体验差异。

### 11.3 社区与贡献

- **学校模板**：`thesis-templates/<school>/<degree>/<year>/template.json` + `SOURCE.md`（来源/日期）+ 脱敏样例；PR 合并前跑 schema 校验与样例回归。
- **规则包**：`rules/` 下的 JSON/YAML；每条规则带 `source`、`version`、`test`；CI 用样例论文验证误报/漏报。
- **引用适配器**：Crossref/OpenAlex 内置；社区可加公开 API 适配器；明确禁止爬取知网/维普/万方。
- **文档/翻译**：README、上手视频、FAQ、英文翻译。
- **Issue 模板**：bug / 模板请求 / 规则误报 / 功能建议；误报必须附脱敏片段。
- **治理**：`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`good first issue`；模板与规则由 maintainer 审核来源与版权。

### 11.4 许可证

本项目采用 **Apache-2.0**（2026-11-20 确定）。根目录 `LICENSE` 为完整协议文本，`NOTICE` 记录版权归属；`desktop/package.json` 已同步为 `"license": "Apache-2.0"`。

选择理由：最大化采用、允许商业使用、专利授权明确；代价是别人可以拿去做闭源托管服务。若以后需要防止闭源 SaaS，可在新版本改用 AGPL-3.0，或对托管版单独商业授权；但已发布的 Apache-2.0 版本不可撤回。

### 11.5 后续商业化（可选，不急）

- 托管服务：不想自己装/配 Key 的用户，按月付费；
- 院系版：多用户、班级、审计、模板管理、校内自托管；
- 技术支持/定制模板/培训；
- 赞助/捐赠。

**边界：核心开源版不缩水、不加付费墙、不强制账号、不上传论文。** 商业化只卖「托管/协作/服务」，不卖「能不能导出修复后的 docx」。

### 11.6 开源指标

- GitHub：stars、forks、release 下载量、issue 首次响应时间、PR 合并率；
- 使用：首次体检完成率、完整文档上传数、修复成功率、复检率（默认无遥测，用可选匿名统计或用户自报）；
- 社区：外部模板数、规则 PR 数、贡献者数、文档翻译数；
- 质量：格式问题检出准确率、误报率、docx 修复失败率。

## 12. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| 季节性 | 使用集中在 2–6 月，非毕业季冷清 | 非毕业季做开题/文献/模板更新；开源版不背订阅收入压力 |
| 社区冷启动 | 没人用/没人贡献 | 样例论文 + 5 分钟上手 + 3 个真实案例；先在 2–3 个学校/社群试点 |
| 模板维护 | 学校多、规则变 | 首批 10–20 所；JSON + 版本；社区 PR + 样例回归 |
| 模板版权 | 复制学校模板文件可能侵权 | 只编码规则，不搬运模板原文；`SOURCE.md` 记录来源；必要时只提供用户自带模板 |
| 引用数据访问 | 中文库无公开 API | 用户 PDF、公开元数据、人工确认；不爬库 |
| 核验准确率 | 误报/漏报 | 规则优先；显示置信度；人工确认；不承诺结果 |
| 模型差异 | 不同模型判断不一致 | 规则优先；LLM 只做模糊判断；显示置信度；用户可换模型复跑 |
| docx 修复破坏文档 | 信任崩塌 | 备份、预览、撤销、只改格式；复杂域提示 Word 更新 |
| Word/WPS 兼容 | 修复后打不开/排版变 | 先 Word docx；WPS 兼容测试；LibreOffice 渲染校验 |
| 2C2G | 无法服务多用户 | 本地优先；服务器只做控制面 |
| 学术诚信争议 | 品牌风险 | 明确辅助定位；禁止代写/降重/伪造引用；AI 披露 |
| 政策变化 | 规则失效 | 规则版本化；学校配置；不做检测/降 AI |
| 隐私 | 论文泄露 | 本地、加密、不训练、可删除、默认无遥测 |
| 开源治理 | 贡献质量/方向失控 | CONTRIBUTING、Issue 模板、maintainer 审核；核心保持窄 |
| 维护者精力 | 范围失控 | 单一模式、窄场景、MVP；不做多端/多品类 |

## 13. 不做清单

| 不做 | 原因 |
|---|---|
| 代写/代做/代答辩 | 学术不端、违法、撤销学位 |
| 降重/降 AIGC/绕过查重 | 高风险、检测不可靠、可能越改越假 |
| 伪造/美化引用 | 学术不端；产品应核验而不是制造 |
| 自动生成论文全文 | 多数高校禁止；会被认定为代写工具 |
| 论文买卖/代发 | 违法/学术不端 |
| AI 代替导师评审/签字 | 学术判断必须由人 |
| 数据/图像伪造/美化 | 学术不端；抽检重点 |
| “包过/包盲审/包发表” | 虚假宣传；不承诺结果 |
| 爬取知网/维普/万方 | 版权/ToS 风险 |
| 用学生论文训练模型 | 隐私/知识产权 |
| 通用 AI 写作/聊天 | 免费巨头覆盖、无差异化 |
| 通用导师协作/文档 | WPS/腾讯/飞书/Overleaf 已占 |
| 答辩 PPT 为核心 | 竞争极高、客单低 |
| 移动端/小程序/Web 工作台 | 多端、无编辑、审核/成本 |
| Word/WPS 插件作为 MVP | 第二个入口；先验证桌面模式 |
| 核心功能付费墙 | 开源版的信任基础是「本地能跑、能导出」；不把导出/修复锁在付费后 |
| 强制账号/上传/遥测 | 本地优先；默认无账号、不上传、无遥测 |

2. **确认首批 3 所学校**（建议：1 所普通本科人文社科、1 所师范/综合类硕士、1 所理工本科），收集 2026 模板与学院通知；只编码规则，不搬运模板原文。
3. **做可点击原型**：论文工作台（问题列表 + 证据卡 + 预览/应用/撤销 + 导出包），用 3 个脱敏样例论文跑通；先验证「没有 API Key 也能完成第一次体检」。
4. **公开 v0.1**：GitHub Release + Docker 镜像 + 5 分钟上手视频；招募 30 名 alpha 用户；用 issue/PR/模板贡献决定下一步。
5. **再决定 L3/毕设**：等格式 + 引用 L1/L2 稳定后，再做全文核验和理工毕设复现。

**一句话：Nova 不变成论文工具，Nova 多了一个开源、本地优先的「论文模式」；用户不用换编辑器、不用交论文、不用买会员，带着自己的模型就能在定稿前体检一次。**
