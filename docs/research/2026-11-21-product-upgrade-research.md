# Nova Agent 产品升级调研

日期：2026-11-21

本文记录五项产品升级的调研与已确认方向。分项调研以官方文档、格式规范和一手产品资料为主；本文件只汇总已经确认的事实、产品决策和待核实事项。

## 已确认的产品决策

1. 开发模式对齐主流 Agent 的任务理解、代码编辑、真实验证、后台恢复和扩展能力，同时保留证据、审计和本地执行等差异。
2. 论文模式采用对话式阶段推进，覆盖方向澄清、选题、资料与项目证据、提纲、分段草稿、检查修改和导出。普通文档可以完整代写；学位论文不提供用户无需参与即可提交的整篇代写，不伪造研究、数据或引用，不提供降重或规避 AIGC 检测。
3. 写作质量要求按场景区分语气，减少模板句、空泛总结和同义反复。这是可读性目标，不是“降 AI 率”或检测承诺。
4. 文档与简历采用“文档工作区 + 项目类型”，共用结构化内容、排版、预览、版本与导出能力，不新增互相独立的排版模式和简历模式。
5. 手机工作台优先。通过微信扫码或一次性绑定链接进入，支持进度查看、审批、继续、停止和通知；微信消息通道与独立移动端都是可选适配层。
6. 先形成完整路线图，再按阶段实施。调研或实测可以触发方案调整，但每次调整记录原因、影响和新的验收条件，不静默缩小目标。

## 主线代码检查

- 现有 Agent 已有工具调用、代码引用核验、命令执行、审批、可恢复回合和只读子代理；方向是补齐与重组，不是推倒重写。
- 论文聊天目前主要注入题目、模板、项目说明、DOCX 结构、未处理问题和参考文献，见 `backend/app/core/thesis/chat_context.py`。这能提供上下文，但还不是选题到定稿的阶段状态机。
- 论文前端主要是项目关联、项目说明和写作快捷指令，见 `frontend/src/thesis/WritingPanel.tsx` 与 `ThesisChatPanel.tsx`。需要把这些入口升级为持续推进的项目流程。
- 现有权限与安全边界可复用于手机审批；远程消息不能直接获得比桌面端更高的权限。

## 文案检查范围

宣传页、使用文档、论文聊天、项目构建对话、Agent 系统提示词都需要覆盖。重点处理：

- “让 AI 理解……”“AI 写作助手”等以技术为中心的表达，改为用户正在完成的任务；
- 每段重复解释能力、证据和边界，合并到必要的上下文中；
- “智能、全面、轻松、无缝”等没有可验证含义的形容词；
- 模型回答中机械的总结、重复提醒和固定格式；
- 保留必要的“AI 草稿”“AI 使用声明”等合规名称，不能为了不像 AI 而隐藏实际参与情况。

待分项报告验收后，再形成目标架构、分期功能清单、依赖关系、验收条件和动态调整规则。
