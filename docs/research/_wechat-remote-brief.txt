# 2026-11-21 微信远程控制 Nova Agent：官方能力与架构调研

## 任务与范围

回答：用户希望在手机微信扫码后查看 Agent 工作进度、发送指令、接收完成/待审批通知，哪些微信通道可以实现，如何为本地优先的 Nova 设计安全远程控制。只做调研，不修改产品代码、不配置公众号、不部署。

## 要求

1. 优先使用微信公众平台、企业微信、微信开放平台的官方文档。核实公众号类型、扫码关注与网页授权、OpenID/UnionID、接收文本/事件、被动回复、客服消息时限、模板/订阅通知的准入与限制、IP 白名单、回调公网 HTTPS/ICP 等要求。区分个人订阅号、认证服务号、企业微信应用，避免混为一谈。
2. 对比至少三种架构：公众号消息回调、企业微信机器人/应用、通用手机 Web 控制台（扫码登录 + WebSocket/SSE，微信作为浏览器入口）；必要时说明邮件/Telegram 等替代通道但不扩展范围。
3. 针对本机运行的桌面/本地 Agent，研究内网穿透或用户自有中继的安全选项；不要求暴露本地端口。远程指令必须可认证、可撤销、限时、可审计，危险命令不能绕开权限审批。
4. 提出推荐 MVP：扫码绑定设备/账号、只读进度、手机审批与“继续/停止”、完成通知、后续有限指令；明确微信消息不是端到端加密、不应发送密钥/私有源码，以及个人项目没有认证服务号时的降级方案。
5. 结果写入 `D:/claudecode_project/Nova Agent/docs/research/2026-11-21-wechat-remote-control.md`，中文 Markdown，逐项附来源和“事实/推断/建议”。返回时只报告路径、核心结论、仍待核实或需用户准备的条件。不编辑其他文件。
