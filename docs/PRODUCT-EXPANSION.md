> 日期：2026-11-20  
> 依据：`docs/research/2026-11-20-ai-market-young-users.md`（52 条来源，A/B/C/D 分级）  
> 修订：v2「一个账号、四个工作台」被用户认为不贴合市场需求；v3 改为**结果导向**：不按「学习/数据/阅读」切品类，而按「谁愿意为什么结果付费」切。  
> 性质：产品策略分析，不改代码。

---

## 0. 结论先行

市场给出的信号很直接：

> **年轻人不是不用 AI，而是只为「能交付的结果」付费。**

所以 Nova 不该做「更懂学生的 AI 学习助手」，也不该做四个并列的工作台。更合适的形态是：

**一个本地优先、可验证的 AI 项目工作台，两个市场面，一个差异化模块。**

| 层 | 是什么 | 面向谁 | 商业模式 |
|---|---|---|---|
| **A. 学生项目冲刺** | 4 周做出一个能写进简历、能演示、能经得起追问的项目 | CS / 理工 / 转码学生 | 自助产品 + 小班验证；199–399 元/项目【假设】 |
| **B. Lab Edition** | 高校课程组/实验室的自托管 AI 工作台 | 教师、实验室主任、院系 | 年费 1–3 万元【假设】 |
| **C. 核验模块** | 引用核验、数据/代码复现、AI 使用记录 | 论文/科研场景 | 嵌入 A/B，不单独卖 |

**A 做楔子，B 做收入，C 做差异化。**  
三者共享同一个内核：Agent 循环、沙箱真实执行、`文件:行号` 证据、红-绿修复、BYOK、多用户、桌面本地。

## 1. 五条关键市场事实

> 详细来源与口径见调研文档；这里只列影响决策的部分。数据存在跨来源口径差异，不能直接相加。

| # | 事实 | 数据 | 对 Nova 的含义 |
|---|---|---|---|
| 1 | AI 已普及，付费仍早期 | 生成式 AI 用户 6.02 亿、普及率 42.8%（CNNIC，2025-12）；大学生使用率 99.2%（n=3129）；C 端付费率 3%–13%（高盛）；25% 学生「买过」AI 工具 | 不要做「大众订阅」；「用」不等于「付」 |
| 2 | 高频入口被通用助手占据 | 豆包 3.7 亿、千问 1.62 亿、DeepSeek 1.27 亿 MAU（2026Q2） | 不做通用聊天/搜索；垂直产品必须占住一个交付流程 |
| 3 | AI 教育是「高 MAU、低利润」 | AI 教育应用 MAU 1.2 亿、+340%，但无 C 端盈利案例；学习机 2026H1 销量 -14.2%、硬件净利 <10% | 不做 C 端学习助手/K12；学校/机构付费更稳 |
| 4 | AI 编程是免费战争 | 2025 年中国 AI 编程市场 3.99 亿元；Trae/通义灵码/CodeBuddy 个人版免费；阿里系份额 47.6% | 不做通用 AI 编程/IDE；做项目结果、证据、课程/实验室 |
| 5 | 求职与科研是「结果强、愿付费」 | 2026 届毕业生 1270 万；简历服务 99–699 元（行业样本）；97% 学生遇到 AI 错误、55% 遇到假参考文献 | 卖「项目证据/求职结果」，不卖「再改一版简历」 |

补充信号：

- **AI 陪伴**高粘性但 2026-07-15 起受专门监管，Nova 不碰。
- **AI Agent** 从「尝鲜」转向「交付」：Manus ARR 1 亿美元，但 Web UV 较峰值 -70%；用户为「可靠完成工作流」付费，不为演示付费。
- **高校**正在本地化部署大模型：实验室项目预算 200–630 万元；这是 Nova 自托管/多用户/BYOK 的真实机会。
- **学生担心的不是 AI 太笨，而是 AI 编造**：97% 遇到错误/虚假信息，52% 浪费时间核验；这与 Nova 的证据能力直接对上。

## 2. 市场结论

1. **通用助手赢在入口，垂直产品赢在交付。**  
   聊天/搜索/问答会被豆包、千问、DeepSeek 吸走；只有「帮我做完并交付一个结果」的工作流能留住人。

2. **学生端的付费锚点是「求职结果」，不是「学习过程」。**  
   学生愿意为简历、面试、项目作品集付费；不愿意为「AI 学习工具会员」长期付费。

3. **机构端的付费锚点是「数据不出校 + 模型自选 + 代码真能跑」。**  
   高校有预算，但要求本地部署、多用户、审计、沙箱、BYOK；这正是 Nova 现有能力的组合。

4. **非 CS 的通用学习/数据/阅读需求很大，但付费弱、竞争强。**  
   市场证据不支持一上来做「所有大学生」的通用产品；先服务愿意为结果付费的窄人群，再扩项目类型。

## 3. 为什么上一版「四个工作台」不行

| 问题 | 说明 |
|---|---|
| 品类思维 | 「学习/数据/阅读」是按产品形态切，不是按用户愿意付费的结果切 |
| 没有付费楔子 | 每个工作台都很大，但没有一个能回答「谁在什么场景下立刻掏钱」 |
| 低估获客 | 新 UI 不会自动带来用户；Nova 没有内容/社区团队，四线作战必死 |
| 没用好桌面端 | 2C2G、ICP/HTTPS 是公开 SaaS 的硬约束；桌面本地模式才是当前最强分发与算力资产 |
| 范围失控 | 四个工作台 = 四套数据模型、四套 UI、四套内容，个人项目无法同时做好 |

v3 的改变：**不按品类建工作台，按「项目结果」建一条产品线。**

## 4. 新产品结构：一个引擎，两个市场面，一个模块

```text
Nova 内核（不重写）
  Agent 循环 · 沙箱执行 · 文件:行号证据 · 红-绿修复 · BYOK · 多用户 · 桌面本地
        │
        ├─ A. 学生项目冲刺
        │     项目模板 · 4 周检查点 · 代码审查/测试 · 证据报告 · 作品集页 · 面试追问
        │
        ├─ B. Lab Edition
        │     课程/班级 · 学生账号 · 作业模板 · 测试/批改 · 证据报告 · 审计 · 校内自托管
        │
        └─ C. 核验模块
              引用核验 · 数据/代码复现 · AI 使用记录
```

### 4.1 不做四个工作台，做「项目轨道」

学生端不再分「学习模式/数据模式/阅读模式」，而是在**同一个项目工作台**里选轨道：

| 轨道 | 适合谁 | 交付物 |
|---|---|---|
| Web 应用 | CS / 软件 / 转码 | FastAPI + React 项目、测试、部署链接、证据报告 |
| 数据分析 | 商科 / 社科 / 理工 | Python + SQL 分析、图表、结论、复现报告 |
| AI 应用 / Agent | CS / 理工 / 创业者 | 可运行的 AI 应用、工具调用、评测记录 |
| 研究复现（后期） | 研究生 / 论文 | 论文代码复现、数据核验、引用清单 |

轨道 = 模板 + 提示词 + 检查点 + 测试 + 证据模板 + 演示脚本 + 面试追问。  
这比「四个工作台」小得多，也直接复用现有的 Builder、verify、evidence、impact。

### 4.2 为什么是「项目冲刺」而不是「学习助手」

- 学生要的不是「学完一门课」，而是「拿到一个能写进简历、能演示、能回答面试追问的项目」；
- 项目有明确开始/结束/交付物，适合按项目收费；
- 项目结果可验证：代码能跑、测试能过、引用能查；
- 项目可以变成作品集、简历条目、面试素材，传播性强；
- 它不鼓励代写：过程留痕、证据报告、面试追问，反而要求学生讲清楚。

## 5. A：学生项目冲刺（0–90 天验证）

### 5.1 目标用户

- 大二–研一的 CS / 软件 / 数据 / 电子学生；
- 22–28 岁转码、求职、留学申请者；
- 首期只做 CS / 理工 / 转码，第二轨道「数据分析」覆盖部分非 CS。

### 5.2 承诺

> **4 周，做出一个能写进简历、能当场演示、能经得起追问的项目。**

### 5.3 交付物

1. 可运行的项目（本地/部署链接）；
2. 测试与运行日志；
3. `文件:行号` 证据报告（哪些代码、哪些测试、哪些结论）；
4. 3 分钟演示脚本；
5. 面试追问清单（基于项目和证据生成）；
6. 可分享的作品集页（脱敏、可导出）。

### 5.4 产品形态

- **桌面端本地运行优先**：不依赖 2C2G、不依赖 ICP/HTTPS；本地模式不需要 Docker（HostExecutor），降低学生安装门槛；
- **BYOK / 免费 GLM**：学生没有 API Key 也能先用免费模型，之后可换自己的；
- **项目模板 + 4 周检查点**：每周一个可验收的里程碑；
- **Agent 做三件事**：代码审查、测试/修复、证据报告；不替学生写完整作业；
- **作品集页**：把项目、证据、演示脚本、面试问答打包成一个可分享页面。

### 5.5 验证方式（不是直接做大产品）

- 15 名学生访谈 + 5 名教师/就业中心访谈；
- 落地页 + waitlist（目标 100 人）；
- 首期 20–30 人小班，99 元押金/首期免费；
- 4 周交付，收集 3–5 个可运行项目与案例；
- 第二期测试 199–399 元付费转化。

**小班是验证与案例渠道，不是最终商业模式。**  
最终产品是自助式「项目冲刺包」；小班用来验证需求、打磨模板、产出案例。

### 5.6 定价假设

| 产品 | 价格 | 依据 |
|---|---|---|
| 首期小班 | 99 元押金/免费 | 降低尝试门槛 |
| 项目冲刺（自助） | 199–399 元/项目 | 简历服务 99–699 元（行业样本）[S52] |
| 月度自学版 | 39–69 元/月 | 学生价格带 30–100 元/月【假设】 |

### 5.7 Kill criteria

- 两期小班后付费转化 <20%，或完成率 <40% → 停止学生端，转 B/C；
- 若完成率高但付费低 → 改为免费获客 + B 端/增值。

## 6. B：Lab Edition（90–180 天验证）

### 6.1 目标用户

- 高校计算机/软件/数据/电子类课程教师、实验室主任、研究生导师；
- 正在做 AI 课程改革、数据不能出校、已有 GPU/私有云的院系。

### 6.2 承诺

> **把 AI 变成课程基础设施：数据不出校，模型自己选，代码真能跑。**

### 6.3 功能包

- 一键 Docker Compose 部署；内网/离线可用；
- 管理员控制台：课程/班级、学生账号、配额、审计日志；
- 课程空间：作业模板、测试/批改、证据报告、复现环境；
- 模型：BYOK（16 家）、本地 Ollama/vLLM、学校统一 Key；
- 安全：沙箱隔离、网络白名单、只读文件系统、资源限制、数据删除；
- 不做：LMS 深度集成（先导入/导出）、移动端、通用聊天、情感陪伴。

### 6.4 验证方式

- 10 名教师/实验室主任访谈；
- 选 1 门课 + 1 个实验室做 2–3 个 pilot；
- 目标：1 个付费 LOI；教师每周节省 ≥5 小时；≥60% 学生周活；
- 定价假设：1–3 万元/年（≤100 用户），院系版 5–10 万元/年【假设】。

### 6.5 为什么适合 Nova

Nova 已经有多用户、BYOK、沙箱、审计、配额、管理员面板、桌面/服务器双模式；缺的是课程/班级/作业/批改/证据报告这一层，而不是重写内核。

### 6.6 Kill criteria

- 6 个月内 <2 个 pilot 或无付费 LOI → 转 A/开源/开发者市场；
- 若教师只用聊天、不用执行/批改 → 说明价值主张不成立，收缩。

## 7. C：核验模块（嵌入 A/B）

- **引用核验**：逐条来源、页码、原句；标记「原文存在/找不到/页码不符」；
- **数据/代码复现**：跑论文/作业代码，比较结果；
- **AI 使用记录**：按高校规范导出 AI 使用说明与对话摘要；
- 目标用户：毕业论文学生、研究生、实验室、图书馆；
- **不单独卖**：学生付费弱、季节性强；作为 A/B 的差异化功能。

## 8. 明确不做

| 方向 | 为什么不做 |
|---|---|
| 通用 AI 学习助手 / K12 | 巨头免费、C 端不赚钱、教研/内容壁垒、学术诚信风险 |
| AI 陪伴 / 情感 | 监管（2026-07-15 新规）、内容风控、IP 运营，非 Nova 优势 |
| 通用 AI 编程 / IDE | 免费战争、大厂卡位、市场仅 3.99 亿元 |
| AI 搜索 / 浏览器 | 索引/内容/流量/资本密集 |
| AI 视频 / 图像 | GPU/模型/内容生态密集 |
| 校园社交 / 社区 | 运营/审核/冷启动，无团队 |
| 纯简历润色 | 同质化、低客单、LLM wrapper |
| 移动端优先 | 无移动端；学生深活仍在电脑 |
| 大众消费订阅 | 付费率 3%–13%、CAC 高、ICP/2C2G |
| AI 代写 / 降 AIGC | 学术不端、检测不可靠、伦理风险 |

## 9. 对现有产品的要求

不需要四个工作台，也不需要重写内核。需要加的是：

| 新增 | 说明 | 复用 |
|---|---|---|
| 项目轨道模板 | 模板、检查点、测试、证据模板、演示脚本 | Builder、verify、evidence |
| 证据报告导出 | `文件:行号` + 测试日志 + diff，导出 PDF/HTML | 交付报告、轨迹 |
| 作品集页 | 项目 + 证据 + 演示 + 面试问答，可分享 | 仓库导出、Markdown |
| 面试追问生成 | 基于项目/证据生成问题与参考回答 | Reviewer、impact |
| 课程/班级层 | 课程、学生账号、作业、批改、审计 | 多用户、配额、管理员面板 |
| 本地优先引导 | 桌面端一键项目、模型配置、无 Docker 路径 | 本地模式、桌面壳 |

**现有开发工作台保持原样**：A 是在它上面加「项目冲刺」模板与证据导出；B 是加「课程/班级/批改」管理层。不是另起炉灶。

## 10. 获客

### A

- 校园社团/班级群/QQ群：2–3 个高校 CS 社团做首期；
- B 站/小红书/知乎/牛客：项目 before/after、代码跑通、面试追问、作品集；
- 创始人 build in public：每周一个真实项目进展；
- 就业中心/辅导员：合作做项目冲刺营；
- 不做泛抖音投放，不投付费广告。

### B

- 2–3 位种子教师/实验室主任；
- 教学会议、教师微信群、知乎/公众号；
- 课程案例：作业自动批改、论文复现、数据不出校；
- 不接定制，不做深度 LMS 集成，先导出/导入。

## 11. 90 天验证计划

| 阶段 | 时间 | 动作 | 指标 |
|---|---|---|---|
| 验证 | 第 1–2 周 | 15 学生 + 5 教师访谈；落地页/waitlist；2 条项目轨道 | ≥50% 确认痛点；≥30 waitlist |
| 招募 | 第 3–4 周 | 2 个校园社团 + B站/小红书/牛客；20–30 人；99 元押金 | ≥20 人开课 |
| 交付 | 第 5–8 周 | 4 周项目；每周 office hour；Agent 审查/测试/证据 | ≥60% 完成；≥50% 部署 |
| 转化 | 第 9–12 周 | 199–399 元付费版；5 个案例；教师 pilot 准备 | 付费 ≥30%；NPS ≥40 |
| 决策 | 第 12 周 | Go/No-go | 付费与完成率达标则继续；否则转 B/C |

### 关键指标

- 激活：首次跑通测试 / 首次导出证据报告；
- 完成：项目部署 + 证据报告导出；
- 付费转化：付费人数 / 开课人数；
- 留存：第 4 周活跃 / 第 1 周活跃；
- 教师提效：批改/备课时间节省；
- 部署时间：从下载到第一个项目可用。

## 12. 风险与假设

| 风险/假设 | 说明 | 应对 |
|---|---|---|
| 学生付费低 | C 端付费率 3%–13% | 押金/预售；低价；B 端兜底 |
| 小班服务重 | 个人开发者难以长期带班 | 模板化；限制人数；小班只做验证 |
| 教师采用慢 | 采购链长、信任不足 | 种子教师；免费学期；案例 |
| B2B 销售/支持重 | 个人开发 | 只做标准版；2–3 个 pilot；不接定制 |
| Docker/环境门槛 | 学生电脑配置差异 | 桌面本地模式不需要 Docker；提供引导 |
| 2C2G 限制 | 多用户/沙箱并发 | 桌面执行；服务器只做控制面 |
| ICP/HTTPS | 公开 B2C 受阻 | 桌面/校内自托管优先；备案后再公网 |
| 学术诚信 | 项目/作业边界 | 定位求职/项目能力；过程留痕；不做代写 |
| 假设未验证 | 199–399 元、1–3 万元/年、教师采用、证据价值 | 用访谈、预售、pilot、LOI 验证；不把假设当事实 |

## 13. 决策建议

- **要用户规模/影响力**：先做 A，项目轨道从「Web 应用」扩到「数据分析」，再扩「研究复现」；
- **要收入/可持续**：B 是更稳的付费引擎，但需要教师渠道与 2–3 个 pilot；
- **要长期差异化**：C 是护城河，但只作为模块，不单独卖；
